# Version-Issues-Hub v0.0.0.2

[GitHub issue #7](https://github.com/vixttha/Version-Issues-Hub/issues/7) fixes the workflow that always published issue #1 and used the latest branch revision as its fix.

## Batch receipts

Pin each issue version to its full fix commit SHA in `ledger/receipt-scope.json`. Create the fix commit first, then add its pin in a separate commit. Keep historical pins in `fixes` and use `versions` to select the issues to verify together. The ledger supplies the corresponding issue number, URL, baseline, target, and acceptance criteria.

The workflow writes one JSON receipt per selected issue version. `fix_sha` identifies the pinned fix, `candidate_sha` identifies the push revision or PR head, and `tested_sha` identifies the actual checkout. A PR run also checks that the checkout's parents are the specified base and head. Every selected fix must be in the candidate's Git history. Integrate with a merge strategy that preserves those commit IDs if subsequent runs use the same pins.

## Historical two-checkpoint pilot

The historical two-checkpoint dogfood test compared the two JSON receipts from draft PR #2 before and after a docs-only commit. Both runs mapped issue #1 to `v0.0.0.1` and issue #7 to `v0.0.0.2`, with distinct fix SHAs. Candidate and tested SHAs changed while both fix SHAs stayed the same. Later scopes produce one receipt per selected checkpoint; they are not restricted to two. See issue #7's original archived runs and issue #13 for the clarification.
