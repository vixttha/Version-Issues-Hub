# v0.0.0.3 — standalone installation candidate

## Installation contract

Owner-locked [feature #9](https://github.com/vixttha/Version-Issues-Hub/issues/9). A pinned VIB package installs only on the dedicated `Version-Issues-Hub` branch of a target GitHub repository. It creates a new tree containing only the package allowlist and adopter-specific state. Its parent is the observed product default commit, but its tree contains no copied product files. Never merge this branch into the product branch. No Provenistem dependency, service, database, paid runner, or ruleset is installed.

Use an authorized cloud shell or agent execution host with Python 3 and a GitHub credential restricted to the selected repository (Contents write, metadata read for apply). Pin and review the source commit containing the installer before executing it. Source revision must be a full SHA from VIB; no mutable branch name. The current candidate is not a public release or license grant.

```sh
python tools/install.py --target OWNER/REPO --source-sha FULL_VIB_COMMIT --baseline v0.0.0
# Review the JSON plan, then repeat with --apply to create the dedicated ref.
```

The default is read-only. A new repository needs an initial commit on its product default branch, created by its owner. Existing installations are refused, not overwritten. Retry after ambiguous API failure by inspecting the branch; never force-update it. The JSON success output records installed commit/tree and source SHA; the in-branch manifest records source SHA, target ID, starting product revision, package digests, and baseline. The initial issue ledger is empty and uses the target repo. Existing numeric three-part baselines such as v1.0.6 are supported with next-patch target v1.0.7. No automatic GitHub rules, product workflows, release, or installation into other repositories is implied.

The installed validator presently validates the adopter ledger; cross-checkout product receipts, trusted policy and merge enforcement remain separate work. The installer tests simulate the GitHub API, including branch collision and a create-ref race. Live external adoption is the fourth phase, not claimed by these unit tests.
