## Self-use preflight

Before every product edit, Head reads the live canonical installed SHA and ledger/handoff, validates identity/package, and compares all mappings and acceptance criteria against the authorized engineering projection. Use `python -m tools.self_use_preflight --installed-ref EXACT_SHA --issue ISSUE` from the engineering checkout after fetching the exact installed ref. Ref freshness must be checked separately immediately before any mutation. A stale/missing/contradictory assignment, wrong active issue, missing handoff or invalid singleton state stops work. Branch-only experiments cannot allocate checkpoints. Batch three means three independent lifecycles, staged separately against actual product PR if needed; no umbrella. Record each original fix SHA and exact candidate evidence. Do not close an issue just because a test passed; explicit Head disposition and issue-specific receipt required. This is a project-local cooperative check, not mandatory branch protection or a trusted security boundary. No installed package modification or automatic upgrade.
