# v0.0.0.34 — Historical acceptance criteria integrity

## Immutable acceptance criteria

Issue #70 preserves the ordered acceptance list for every previously assigned issue when validating ledger history. Silent replacement, addition, removal or reordering is refused even when the issue-version binding is unchanged. Legitimate state transitions, row reordering and new issue assignments remain allowed. Existing criteria are not rewritten. Any future amendment mechanism requires an explicitly reviewed design; this checkpoint does not introduce one. Installed packages remain pinned until an authorized upgrade.

## Graphify capacity compatibility

Public qualification exposed the pinned upstream template limit of 32 features at the 33rd record. Split the full evidence inventory into ordered shards of at most 32, preserving every feature and the original full manifest. Each shard must independently pass the upstream Graphify MCP check and its receipt must bind exactly its feature IDs, source SHA and graph digest. The artifact includes `shards.json` with receipt digests; single-shard outputs retain the original paths. No upstream package change or historical evidence deletion.
