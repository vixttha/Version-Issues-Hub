# v0.0.0.36 — Explicit receipt selection integrity

## Validate the complete selection before generating receipts

Issue #72 prevents empty, duplicate, malformed and unpinned explicit version selections from reaching receipt generation or ancestry checks. A valid ordered list or tuple is accepted; default scope remains unchanged. A historical singleton may select any recorded fix even outside the current default selection. Original fix pins, candidate ancestry checks, and scope validation are preserved. No package migration or version reassignment.
