# v0.0.0.41 — Scope control and experimental disposition (#92)

This checkpoint adds a cooperative source-scope guard to VIB self-use, not a new mandatory adopter service or authenticated authorization layer. The owner delegated implementation under the four immutable #92 criteria. The bounded path set was recorded independently of the engineering candidate in the canonical installed branch at 5a42e6526c783b75996dc25137ae9efb3ca86ee5, under `ledger/scope-approvals/v0.0.0.41.json`. The installed package itself is unchanged. The generic checkpoint preflight requires a canonical approval from .41 onward: exact issue/version/criteria, base, reviewed revision, qualification and disposition, current record and ancestry. It compares the full candidate tree against the approved engineering baseline using a NUL-delimited, rename-disabled diff. Deletions, moves and new files are included. A candidate cannot widen its own allowlist by changing a local JSON file. All changes still require exact-head review; a path allowlist is not semantic approval of arbitrary edits within a path.

For a later amendment, the owner must approve the exact prior canonical approval and new reviewed engineering revision, keep original baseline and criteria, and publish the revised record via the canonical ref with a non-force expected-old lease. Retain prior Git history. The updated Worker pin must reference the actual latest scope-policy commit, and validation checks the exact predecessor through first-parent path history, rejects stale or restored old approval values, and requires the reviewed amendment revision to remain within the prior scope. Scope publication must be a separate single-parent commit changing only that policy file. The legacy explicit preflight route cannot bypass scope-controlled checkpoints. Never self-approve an amendment in the Worker branch. A changed PR base requires a newly approved scope process; the current checkpoint does not authorize one. A separate trusted reviewer must inspect any change to the preflight itself. These are cooperative guards: a privileged writer can alter refs or code, and no signature or branch protection is claimed.

Parallel schema decoding is retained for historical inspection. New activation and publication of experimental parallel state, and normal Standard/gate promotion from such state, refuse by default. A separate owner-reviewed source decision is required; `--parallel`, a capability marker or a runtime environment setting is not activation authority. Small historical synthetic tests use in-process test-only patches to exercise retained behavior, not operational activation. The four suspended advanced qualification methods remain skipped. Self-use #37/#40/#53 cannot be claimed or published through the ordinary workflow or promoted by production evidence. Existing dispositions and all mappings are preserved.

No production merge, release, live package migration, advanced trial or .42 implementation is authorized. Read-only historical inspection remains available. Ordinary public runners and exact revision evidence remain the qualification boundary.
