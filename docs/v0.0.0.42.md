# v0.0.0.42 — Simplified recovery, handoffs and evidence reuse (#94)

Use the opt-in read-only command:

```sh
python -m tools.session --target OWNER/REPO --expected-sha STATE_SHA inspect --issue ISSUE --recovery-plan
```

The advisory checks the installed lease before and after reading canonical state. It distinguishes the existing workflow phase, other active issue, staged issue, stale candidate/integration, merged or closed PR, pending closure, owner hold and experimental history. A recommendation is not an authorization or a mutation. The default inspect output is unchanged.

Recorded links are considered only from the exact requested active/staged handoff. Reuse requires a fix/candidate/PR/base/proposed-merge tuple, fix ancestry, fresh exact run/attempt association and re-read of current integration pins. Archived stale run IDs and runs recorded against another fix are rejected. Changed or missing evidence yields no reusable links. No links are copied from other issues or silently promoted into a new phase. Even an exact-run revalidated reference is not a new test execution, independent audit or integration verdict.

The singleton workflow, owner holds, original histories and closure records are retained. No automatic merge, issue closure, production integration, package migration, new dependency, advanced qualification or experimental activation is introduced. Qualification uses ordinary public runners and exact evidence; the four previously suspended advanced methods remain suspended.

Evidence revalidation is followed by a fresh read-only inspection. If the PR or issue changed, stale phase guidance and reusable links are suppressed. A failed run revalidation requires a fresh exact evidence review, not an advance. An unverifiable final observation stops guidance.
