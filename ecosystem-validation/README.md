# Six-tool engineering ecosystem validation (non-product workspace)

Owner-approved architecture: ENGINEERING-ECOSYSTEM-LAWS-001. This is a disposable validation and planning workspace, not a seventh tool. No mandatory coordinator, shared service or dependency is introduced.

## Discovery and distribution
Each independent tool embeds the same marker schema in its existing documentation. Enumerate actual repository refs, pin the selected commit, read its own entrypoint, validate identity and law block. Missing or legacy branches are not automatically installed; no marker grants authority. Humans use the product's own reviewed install guide; agents use equivalent authorized Git operations. Record source, target, version, changes, evidence and owner decision; preserve existing records and product branch. Do not treat an unmerged candidate as a release.

## Compatibility
The public-runner script projects six real, pinned product source trees into isolated Git branches and enumerates all 64 subsets (63 nonempty + baseline), verifies exact marker identity and law parity, and checks that discovery never changes refs. Negative controls: wrong identity and missing marker. Product-native CI and live installation tests remain separate. This does not execute every product runtime in every combination or claim live installation into 63 GitHub repositories.

## Performance
Pilot: compare two fresh sessions of the same agent on the same historical BART issue #69 recovery task. Control uses ordinary issue/PR/Actions records, intervention can additionally use the exact VIB snapshot. Score exact issue version, candidate SHA, proposed merge SHA, CI run ID, pass count, actual merge SHA, next action, release authority (8 binary items). Record source citations, model unknown, task constraints, tool counts if observable; no claimed token/cost savings absent telemetry. This tests VIB-assisted recovery only, not all six tools or software coding productivity. Full benchmark requires preregistered comparable implementation tasks, independent fresh sessions, equal model/tool budgets, randomized arms, hidden tests and repeated trials; measure accepted fixes, regressions, owner interventions, time/tokens/cost only when available. Never claim improvement from test availability or synthetic scoring.

## Commercialization proposal (not approved branding or launch)
Working category: **agent engineering toolkit**. Working positioning: Six independent GitHub-native tools that provide a durable, owner-controlled engineering environment for compatible agents. Target: solo developers and small software teams using GitHub and coding agents. Demonstration: begin with an issue, recover exact scope, verify tests, archive evidence, update documentation and record owner decision. Sell no performance guarantees before measured data. Free/open source availability depends on each product's license; paid options to research: installation/setup services, support, training and optional hosted conveniences, never a mandatory paid service. No final collective name, price, trademark claim, license change, or public launch authorized. Confirm each product's reuse terms and dependencies before bundling or commercial distribution.
